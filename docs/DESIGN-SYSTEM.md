# 디자인 시스템

작성: 2026-10-16 (0단계) · 개정: 2026-10-17 (편집 작업대 구조, Tracwell 테마, 생방송 영상 카드) · 절차: frontend-design 스킬 (계획 → 기본값 점검 → 구현 → 스크린샷 점검)

> 2026-10-17 사용자 요청으로 화면 구조를 "편집 작업대"로 바꾸고, [Tracwell](https://tracwell.app/)의 테마·카드·디자인을 "최대한 적용"했습니다. 처음의 참고 이미지 색(흑백 + 눈동자 파랑 + 볼 홍조)과 "카드 대신 구분선" 원칙은 이 결정으로 교체했습니다(6절 기록).

## 1. 주제와 사용자

- **무엇**: 방송 채팅에서 반응이 몰린 구간을 찾아 편집할 순간을 고르는 로컬 작업 도구.
- **누가**: 방송 편집자와 방송자. 몇 시간짜리 다시보기·생방송 옆에 오래 띄워 두고 씁니다.
- **주된 일**: 시간축 위에서 반응이 몰린 곳을 빠르게 찾고, 그 시각으로 이동해 확인하는 것.
- **빌려 올 언어**: 영상 편집 프로그램(NLE)의 타임라인, 마커, 타임코드, 재생 위치. 겉모습은 Tracwell(웹 분석 앱)의 중립 바탕·카드 셸·데이터 색입니다.

## 3. 서체

- **본문**: 운영체제의 UI 서체(macOS SF Pro, Windows Segoe UI, 설치되어 있으면 Inter)로 영문·숫자를 쓰고, 한글은 운영체제 한글 서체(`Apple SD Gothic Neo`, `Malgun Gothic`, `Noto Sans KR`)로 이어집니다. Tracwell은 Inter를 내려받아 쓰지만, 이 앱은 실행 중 외부에서 서체를 받지 않고 서체 파일을 넣으면 실행파일이 커지므로 넣지 않았습니다. 운영체제 UI 서체에는 고정폭 숫자가 있어 타임코드가 흔들리지 않습니다.
- **제목**: Tracwell의 둥근 제목 서체(`Open Runde`)가 있으면 쓰고, 없으면 `ui-rounded`(Safari) 또는 본문 서체로 씁니다. 자간 -0.03em, 굵기 600, 줄 간격 1.05로 Tracwell 제목 모양을 맞춥니다.
- **크기**: 13 / 14(본문) / 16 / 20 / 30 / 44(새 작업 제목)px. 요약 숫자는 20px 600, 자간 -0.03em.
- 제목 안의 한 단어만 강조하지 않습니다.

### 앱 틀

```text
┌ 사이드바 (17rem, 연한 회색) ┬──────────────────────────────────────────┐
│ ▮▮▮ MomentForge        [⊟] │  (페이지)                                    │
│ ( 새 작업 )                │                                              │
│ 저장한 작업                │                                              │
│ ┌────────────────────┐     │                                              │
│ │ 열린 작업 (흰색 들뜸) │     │                                              │
│ └────────────────────┘     │                                              │
│   다른 작업                 │                                              │
│ ⚌ 설정                      │                                              │
│ › 목록 정리                 │                                              │
│ ┌ ● 연결됨    버전 dev ┐    │                                              │

```

- Tracwell 앱 견본처럼 사이드바는 연한 회색이고, 열린 작업은 흰색에 얇은 테두리로 떠 보입니다. 아래쪽에 설정, 목록 정리, 연결 상태 카드를 둡니다. 설정은 작업 행과 같은 조용한 줄(슬라이더 아이콘)이고, 열려 있으면 흰색으로 떠 보입니다.
- 넓은 화면에서는 **작업 목록 접기**로 좁은 막대(펼치기, 새 작업, 맨 아래 설정)로 접고, 이 선택을 브라우저에 기억합니다.
- 860px 미만에서는 Tracwell 머리글처럼 떠 있는 둥근 상단 막대(작업 목록 버튼 + 앱 이름)를 두고, 목록은 왼쪽 서랍으로 엽니다. 서랍은 열릴 때 포커스를 가져가고 Esc로 닫힙니다.

### 새 작업 (처음 화면)

```text
┌ 연한 띠 (surface + 파랑·라일락 빛) ───────────────────────────────┐
│ 새 작업                                                          │
│ 방송 채팅에서 편집할 순간을 찾습니다.                              │
│ ┌ 떠 있는 틀 (그림자) ──────────────┐  ┌ 처음이라면 (복숭아) ┐    │
└─│ ( 다시보기 | 생방송 )              │──│ [샘플로 먼저 체험]  │────┘
  │ 주소 입력, 옵션, [수집하고 편집점 찾기] │  └────────────────────┘
  └────────────────────────────────────┘  ┌ 앱 정보 ────────────┐
  (작업 진행 카드)                          │ 지원 플랫폼 …       │
  이렇게 진행됩니다                          └────────────────────┘
  (① 주소 넣기)(② 채팅 수집과 분석)(③ 후보 확인과 내보내기)
```

- (2026-10-17 개정) 오른쪽 칸은 사용 경험에 따라 바뀝니다. 저장한 작업이 없으면 "처음이라면"(복숭아, 샘플 버튼)과 왼쪽 아래 세 단계 카드를 보여 주고, 작업이 생긴 뒤에는 단계 카드를 빼고 **최근 작업**(새 순서 4개, 제목과 요약 한 줄, 누르면 그 작업)과 "샘플 다시 보기"를 둡니다. 앱 정보(버전·지원 플랫폼·데이터 폴더·스키마)는 설정 화면으로 옮겼습니다. 띠의 높이도 줄였습니다(작업 도구의 첫 화면이라 입력 칸이 빨리 보여야 함).
- 수집 옵션은 짧은 이름을 굵게 두고 설명을 그 아래 작은 회색 줄로 둡니다(`.check-option` + `.check-help`). 괄호 안에 긴 설명을 넣지 않습니다. 설정의 새 작업 기본값도 같습니다.
- **NAS 백업** 탭(2026-10-18, 6-B): 폴더 경로 입력(마지막 폴더를 브라우저에 기억) → **폴더 읽기** → 방송 목록(제목, 날짜·채팅·음성·영상 크기; 불러온 것은 **열기**) → **불러오기**. 옵션은 "방송 내용 인식(전사)까지"(엔진 준비 상태를 설명 줄에)와 "항상 가장 민감하게".
- 다시보기·생방송은 탭입니다. 다른 종류의 주소를 붙여넣으면 맞는 탭으로 옮기고 그 입력칸에 포커스를 둡니다. 직접 쓴 주소가 다른 종류로 보이면 옮기기 링크를 보여 줍니다. 두 탭은 주소 하나를 함께 씁니다.
- 세 단계 카드는 Tracwell의 "How it works" 카드(28px 모서리, 색 띠)입니다. 실제 순서라 번호를 붙입니다.

### 설정

```text
┌ 연한 띠 ─────────────────────────────────────────────────────────┐
│ 설정                                                             │
│ 새 작업과 AI 검토가 시작할 기본값을 정합니다.                       │
│ ┌ 떠 있는 틀 ─────────────────────────┐  ┌ 저장 위치 ──────────┐   │
└─│ ( AI 검토 | 새 작업 기본값 )          │──│ settings.env, .env │───┘
  │ 기본 AI 제공자 (Claude|OpenAI|…)     │  └────────────────────┘
  │ ┌ 시트: 고른 제공자       ● 키 있음 ┐ │  ┌ API 키 (복숭아) ────┐
  │ │ 기본 모델 ID, API 키, □ 이 컴퓨터에도 저장 │ │ 메모리·파일 안내     │
  │ │ (키 저장) 키 지우기  모델 불러오기   │ │  └────────────────────┘
  │ └────────────────────────────────────┘ │
  │ (고른 제공자의 시트 하나만)               │
  │ ─────────────────────────────────────  │
  │ (기본값 저장)  저장하지 않은 변경 …      │ ← 화면 아래에 붙음
  └──────────────────────────────────────┘
```

- 새 작업과 같은 틀입니다: 연한 띠 위로 떠 있는 틀, 오른쪽 시트. 틀 안은 **AI 검토**와 **새 작업 기본값** 탭이고, 저장 버튼은 두 탭 아래에 하나 둡니다. 내용이 길면 저장 줄이 창 아래에 붙어 있습니다.
- 기본 제공자는 `Segmented`이고, 그 아래에는 **고른 제공자의 시트 하나만** 보입니다(2026-10-17 사용자 요청: 제공자를 고르면 그 제공자의 설정이 나와야 함). 다른 제공자를 고르면 시트가 그 제공자로 바뀌고, 그 선택이 기본 제공자가 됩니다. 시트는 이름, 오른쪽에 연결 상태와 같은 점과 낱말(키 있음·키 없음·준비됨·준비 안 됨), 안에는 주소(CLIProxyAPI·OpenCodex, 주소 아래 설명은 제공자가 정함), 기본 모델 ID와 키 입력(또는 Codex·OpenCode·OpenCodex의 준비 상태와 연결 방법)입니다.
- CLIProxyAPI·OpenCodex 시트 맨 위에는 실행 상태 상자(연한 바탕): 점과 낱말(실행 중은 초록, 꺼짐·설치되지 않음은 회색), **<이름> 켜기**(주요 버튼) 또는 **<이름> 끄기**(보조 버튼), 대시보드가 켜져 있으면 **<이름> 대시보드 열기**(보조 버튼, 새 탭)와 제공자가 정한 안내(CLIProxyAPI는 관리 키 파일, OpenCodex는 로그인 없이 열림, 꺼진 대시보드는 켜는 방법), **상태 다시 확인**, 프로그램·설정 파일·기록 경로 목록. 켜고 끄는 동안 낱말이 "켜는 중"·"끄는 중"으로 바뀝니다.
- (2026-10-17 개정) 오른쪽 시트는 **앱 정보**(버전·지원 플랫폼·데이터 폴더·스키마, 새 작업 화면에서 옮김)와 **저장 위치**(기본값 파일·키 파일, API 키 안내를 합침) 두 장입니다. 제공자 시트의 주소 설명과 프로그램·설정 파일 위치는 접힌 줄(`.field-more`)로 두고, 프로그램을 찾지 못했을 때만 펼쳐 둡니다.
- 저장한 기본 제공자가 없어 앱이 시작할 때 고른 제공자면, 제공자 선택 아래에 파란 안내("이 컴퓨터에서 바로 쓸 수 있는 …을(를) 자동으로 골랐습니다")를 둡니다.
- 키 입력·저장·지우기는 AI 검토 탭과 같은 공용 컴포넌트(`shared/ai/AIKeyField`)라 두 화면이 같은 상태를 보여 줍니다. 키는 저장 뒤 다시 보여 주지 않고, 어디서 온 키인지(이 컴퓨터, 환경변수, 이번 실행만) 한 줄로 알립니다.
- 키는 **키 저장**으로 바로 저장하고, 나머지 기본값은 **기본값 저장**으로 한 번에 저장합니다. 바꾼 값이 없으면 저장 버튼은 꺼져 있습니다.

- **카드 셸**(Tracwell 개요 카드): 회색 바깥 틀(16px 모서리, 얇은 그림자) 안에 이름 줄과 흰 안쪽 면(12px 모서리). 영상·채팅·타임라인과 요약 숫자가 이 모양입니다.
- **생방송 작업대**: 다시보기와 같은 무대에 '영상'(지금 방송)·'실시간 채팅'·'반응 타임라인' 카드를 둡니다. 영상 카드는 수집 중일 때만 재생기를 띄우고, 재생을 누르기 전에는 모니터 아래에 "재생하면 영상을 받기 시작합니다" 안내 한 줄을 둡니다. 수집을 멈추면 꺼진 모니터(어두운 면 + 가운데 안내)로 남겨 배치가 흔들리지 않게 합니다. 영상을 받지 못하면 같은 꺼진 모니터 가운데에 경고색 이유와 '다시 불러오기'를 두고, 플랫폼에서 열기 버튼은 머리의 버튼을 그대로 씁니다. 무대가 좁아 영상 위·채팅 아래로 나뉘면 생방송은 채팅을 더 높게 둡니다(영상 1 : 채팅 1.4). 채팅이 이 화면의 일이고, 영상은 10초 넘게 늦는 참고 화면이기 때문입니다.
- **시트**: 흰 카드 한 겹. 도구 패널(연한 바탕) 안의 후보·AI·댓글·파일 묶음입니다.
- 너비 1100px 이상이고 높이 600px 이상이면 화면이 창 높이에 맞춰집니다. 영상·채팅·타임라인은 늘 보이고 오른쪽 도구 패널만 따로 스크롤합니다. 무대가 좁으면(44rem 미만) 영상 위·채팅 아래로 나눕니다. 그보다 작으면 머리·무대·도구가 위에서 아래로 쌓입니다.
- 오른쪽 도구는 탭이며, 고르지 않은 탭도 내용을 유지합니다(입력 중인 AI 설정 등).
- **타임라인이 화면의 중심**입니다. 전체 길이를 한 줄에 그리고, 재생 위치를 세로선으로 표시합니다. 트랙을 누르거나 방향키(5초)로 재생 위치를 옮깁니다. 영상이 없는 작업은 그 위치의 앞뒤 채팅을 보여 줍니다.
- **재생 위치 채팅** 카드(2026-10-17 사용성 개선): 무대가 넓으면 영상 옆 두 번째 열로 폭 `clamp(20rem, 42%, 30rem)`을 차지합니다. 한 채팅은 한 줄입니다: 시각(작은 회색), 가명 키 앞 네 글자의 색 태그(여섯 가지 톤, 같은 사람을 구분하는 용도), 본문. 이모티콘 코드 `{:이름:}`은 이름이 적힌 칩으로 그립니다. 영상이 있으면 모든 행이 버튼이고 누르면 영상이 그 시각으로 갑니다(영상이 없으면 재생 위치만 옮김). 같은 행 모양을 후보의 편집 구간 채팅과 생방송 실시간 채팅에도 씁니다.
- **타임라인 확대와 후보 이동**(2026-10-17): 타임라인 카드 머리에 확대 선택 알약(전체 · 30분 · 10분 · 2분, 작업 길이의 75%보다 짧은 것만)과 **이전 후보**·**다음 후보** 버튼을 둡니다. 확대하면 재생 위치 주변 구간만 그리고(재생 위치가 구간을 벗어나면 구간이 따라 넘어감), 그 아래 얇은 전체 막대에 지금 보는 구간·후보 위치·재생 위치를 표시합니다. 마커에는 마우스를 올리면 후보 번호·시각·이유가 뜹니다. `N`·`P`(자판 위치 기준이라 한글 입력 상태에서도 동작)는 재생 위치 다음·이전 후보로 옮기고, 어떤 방법으로 고르든 고른 후보 행이 후보 목록에서 보이게 스크롤합니다.
- **영상 이동 조작**: 영상 카드 아래에 `−30초 · −5초 · 재생/일시정지 · +5초 · +30초` 버튼 줄과 키 안내를 둡니다. 키보드 `←·→` 5초, `Shift+←·→` 30초, `Space`·`K` 재생/일시정지는 화면 어디서나 같게 동작하며(입력칸·탭·선택 상자에 포커스가 있을 때만 제외), 브라우저 재생기의 기본 키(길이의 1%씩 이동, 포커스에 따라 무반응)는 막습니다.
- 후보 행은 **편집 구간**(잘라낼 범위)을 큰 시각으로 먼저 보여 주고, 반응 구간과 최고점 수치는 아래 한 줄로 둡니다. 행을 누르면 고른 상태가 되고 **영상이 그 구간부터 재생**됩니다(따로 "영상에서 보기" 링크를 두지 않음). 고르면 출처 색으로 물든 카드가 되고, 근거 채팅은 Tracwell의 "Top sources"처럼 건수 비율만큼 옅은 막대가 깔리는 목록입니다.
- **AI 설명**: 고른 후보를 설명한 AI 결과(`sourceCandidateIds`가 그 후보를 가리킴)는 따로 행을 만들지 않고 그 후보 아래 보라 왼쪽 선의 상자로 붙습니다(배지 "AI 설명", 중요도, 장면 한 줄 제목, 설명, AI가 잡은 구간과 "이 구간 재생", 접힌 "판단 한계"). 후보 밖에서 새로 찾은 장면만 "AI 추천" 행과 마커가 됩니다. 요약 숫자와 후보 탭의 개수는 행 수입니다.
- **대본 탭**(2026-10-18, 6-B): 전사가 있으면 찾기 칸, 10분 단위 이전·다음(기본은 재생 위치를 따라감), 발언 목록(채팅 행과 같은 모양, 화자 태그는 민트, 누르면 그 발언으로 이동). 없으면 **방송 내용 인식** 버튼과 안내. 채팅 행의 후원은 복숭아색 💰 금액 태그, 구독은 라일락 ⭐ 태그, 시스템 알림과 봇이 가린 줄은 회색.
- **AI 컷 분석**(2026-10-18, 6-A): 컷 계획도 고른 후보 아래 같은 보라 상자로 붙습니다(배지 "AI 컷 분석", 버전, 초록 "검수 통과"/산호 "검수 실패" 알약, 장면 한 줄, 원인 한 줄, 구간 목록(앞선 맥락·본 장면·마무리, 시각, 재생), 구간 수와 합계, "구간 이어 재생", 검수에 걸린 이유는 경고색 줄). 같은 후보의 새 분석은 이전 상자를 **대체**합니다(버전 표시). 상세 결과 상자(원인 대안, 이야기 기원, 필수 맥락 버튼, 짧게|맥락|전체 전환, 메모·확정)는 6-D에서 더합니다.
- AI 검토 탭 1단계의 **분석 종류** 알약(장면 설명 | 컷 분석): 컷 분석을 고르면 보낼 범위는 "고른 후보"만 남고, 미리보기 요약은 후보 수·후보당 요청 수·읽는 발언·채팅 수를 보여 줍니다.
- AI 검토에 후보를 고르면 패널 아래에 검은 알약 막대("AI 검토에 고른 후보 N개", AI 검토로 이동)가 뜹니다. 누르면 AI 검토 탭이 열리고 보낼 준비가 되어 있으면 미리보기를 바로 만듭니다.
- **AI 검토 탭**은 세 단계로 나눕니다: "1. 무엇을 보낼지"(보낼 범위 선택 알약), "2. 어디로 보낼지"(제공자 · 모델과 준비 상태 점이 있는 한 줄 `details`; 보낼 수 없는 상태면 펼쳐져 있고, 안에 제공자·모델 ID·키·전송 방식·비용 한도), "3. 확인하고 보내기"(미리보기 → 실행). 실행이 끝나면 결과가 어디에 붙었는지와 "후보 보기"를 알립니다.
- **수집 시작 뒤 이동**: 새 작업에서 수집(또는 댓글만 수집)을 시작하면 작업이 저장되는 대로(작업 상태에 `sessionId`가 생기면) 그 작업 화면으로 옮겨 가고, 머리의 진행 카드가 수집 진행을 보여 줍니다.
- **멈춘 생방송 기록**(2026-10-17 개정): 수집이 멈추면 영상 카드는 안내 한 줄짜리 띠로 줄고 실시간 채팅이 그 자리를 차지합니다. 예전처럼 꺼진 모니터를 크게 남기면 나중에 기록을 열었을 때 화면 절반이 빈 칸이 되기 때문입니다.
- **휴대폰 작업대**: 요약 숫자 네 개를 한 줄 네 칸으로 줄이고(이름 11px, 숫자 14px), 채팅 높이를 240px로, 키 안내는 숨깁니다. 영상이 첫 화면에 더 빨리 들어옵니다.
- 생방송 작업대는 영상 대신 실시간 채팅을 두고, 도구 탭은 (후보 | AI 검토 | 수집 상태 | 파일)입니다. 후보 목록은 자동 탐지와 AI 추천을 함께 보여 주며(고른 후보의 AI 설명은 그 후보 아래), 아직 확정되지 않은 후보의 "AI 검토에 포함"은 흐린 글자로 막아 둡니다.

## 5. 원칙

1. **눈에 띄는 것은 타임라인 하나.** 카드는 모두 같은 회색 셸로 조용하게 두고, 색은 타임라인과 후보에 모읍니다.
2. **편집 프로그램처럼 읽힌다.** 시각은 항상 `시:분:초` 타임코드, 후보는 마커, 재생 위치는 세로선입니다.
3. **움직임은 상태 변화에 대한 응답.** 사용자 동작(누름·선택·펼침), 새 데이터 도착(채팅·후보·숫자), 진행 중인 작업(수집·AI)을 보여줄 때만 움직입니다. 예외는 새 작업 제목이 한 번 떠오르는 것뿐입니다. 반복되는 장식 배경, 그라데이션 글자, 커서를 따라다니는 효과는 쓰지 않습니다. `prefers-reduced-motion`이면 지연·반복까지 모두 즉시 끝납니다 (8절).
4. **중립 바탕 위에 데이터 색.** 파랑은 밀도·동작, 산호색은 자동 탐지, 청록은 시청자 추천, 보라는 AI입니다. 같은 출처는 마커·구간·배지·선택 행에서 같은 색입니다.
5. **문구는 할 일을 말한다.** 버튼은 결과로 이름 짓고("수집 시작"), 오류는 원인과 해결 방법을 함께 적습니다. 대문자 라벨, `→` 붙은 버튼, `A · B · C` 식 메타 문자열을 쓰지 않습니다.

## 7. 토큰 구현

`web/src/styles/tokens.css`에 CSS 변수로 정의합니다. 컴포넌트는 이 변수만 사용하고 hex 값을 직접 쓰지 않습니다.

- 간격: 4px 단위(`--space-1`=4px … `--space-8`=48px).
- 모서리: `--radius` 10px(입력칸·행), `--radius-md` 12px(카드 안쪽 면), `--radius-lg` 16px(카드·시트), `--radius-xl` 28px(단계 카드), `--radius-pill`(버튼·탭·배지).
- 그림자: `--shadow-card`(머리카락 테두리 + 얕은 그림자), `--shadow-raised`(선택 항목의 1px 테두리), `--shadow-frame`(새 작업 틀의 깊은 그림자). 다크 모드는 흰색 테두리 위주입니다.
- 버튼: 알약 모양, 주요 버튼은 `--primary` 바탕 + 안쪽 위 1px 밝은 선, 보조 버튼은 `--secondary` 바탕. 포커스는 3px 반투명 파랑(`--ring`).
- 배치: `--sidebar-w` 17rem, `--rail-w` 3.5rem, `--panel-w` clamp(24rem, 30vw, 30rem).

## 8. 움직임

2026-10-17 사용자 요청으로 [Lucian UX/UI Prompt](https://lucianlabs.dev/uxui-prompt/)와 [Tracwell](https://tracwell.app/)의 코드(HTML·CSS·JS)를 분석해, 작업 도구에 맞는 것만 골라 넣었습니다. 사용자는 "작업 도구에 맞게"를 골랐습니다(참고 사이트의 그라데이션 글자·커서 효과·배경 반복 애니메이션·테마 전환 버튼은 제외).

### 토큰 (`tokens.css`)

| 이름 | 값 | 쓰임 |
|---|---|---|
| `--ease-out` | `cubic-bezier(0.2, 0.8, 0.2, 1)` | 자리 잡는 움직임 (Lucian `--ux-ease`와 같은 곡선) |
| `--ease-spring` | `cubic-bezier(0.34, 1.45, 0.64, 1)` | 제자리에 튕기며 맞는 것: 알약, 숫자, 마커 (Lucian `--ux-spring`) |
| `--ease-control` | `cubic-bezier(0.16, 1, 0.3, 1)` | 버튼·링크·목록 행의 색 바뀜 (Tracwell 버튼) |
| `--dur-1` | 150ms | 마우스 올림, 누름 |
| `--dur-2` | 320ms | 패널, 화면 전환, 서랍 |
| `--dur-3` | 560ms | 미끄러지는 알약, 숫자, 새 행, 비율 막대 |

### 규칙

- 움직임은 `transform`·`opacity`·`clip-path`만 씁니다(레이아웃을 다시 계산하지 않음). 긴 다시보기의 막대 수천 개는 하나씩 움직이지 않고 트랙 하나를 쓸어 냅니다.
- 등장 애니메이션은 `animation-fill-mode: backwards`로 둡니다. 끝난 뒤에는 원래 스타일로 돌아가야 선택·마우스 올림 전환이 그대로 동작합니다.
- `prefers-reduced-motion: reduce`이면 길이·지연을 0으로, 반복을 1회로 만듭니다. 줄무늬·빛·고리 같은 반복은 멈춘 그림이 됩니다. 포커스를 옮겨야 하는 요소(서랍)는 열릴 때 `visibility`를 전환 없이 바로 바꿉니다.
- E2E는 움직임 줄이기 환경에서 돌려 클릭과 스크린샷이 움직임 도중에 걸리지 않게 합니다. 움직임 자체는 `e2e/test_motion.py`가 움직임을 켜고 확인합니다.

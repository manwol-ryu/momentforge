# MomentForge

방송 채팅을 모아 **편집할 순간(편집 후보)을 찾는 로컬 앱**입니다. 치지직 다시보기와 공개 생방송의 채팅을 내 컴퓨터에 저장하고, 웃음·채팅 급증·같은 말 반복·감정 반응·참여자 증가가 그 시간대치고 드물게 몰린 구간을 후보로 정리해 강도와 순위를 매깁니다.

- 실행파일 하나(`momentforge`)로 동작합니다. 화면은 실행파일에 들어 있고, `127.0.0.1`에서만 열리는 로컬 서버를 브라우저로 씁니다. 사용자는 Go·Node·Python을 설치할 필요가 없습니다.
- 공개 방송은 방송자 계정이나 개발자 키 없이 수집할 수 있습니다. AI 검토는 선택 기능이며, **설정 › 일반 설정**에서 보낼 내용과 한도에 동의하고 켰을 때, 또는 작업 화면에서 직접 보낼 때만 보냅니다.
- CzzEdit 0.3.2(Python)를 포크해 Go + React/TypeScript로 다시 작성했습니다. 기존 Python 코드는 `legacy-python` 브랜치에 있습니다. 기존 `.czzedit` 데이터는 읽지 않습니다.

치지직 공식 서비스나 제휴 앱이 아닙니다. 치지직 웹이 쓰는 비공식 조회·읽기 연결을 사용하므로 서비스가 바뀌면 수집이 실패할 수 있습니다. 응답 형식이 달라지면 추측하지 않고 오류로 멈춥니다.

## 주요 기능

| 기능 | 동작 |
|---|---|
| 다시보기 수집 | 채팅을 페이지별로 받아 로컬 DB에 저장하고, 중단한 위치에서 이어받기 |
| 생방송 수집 | 공개 채팅을 받으면서 바로 편집 후보를 찾음. 끊기면 자동 재연결하고 못 받은 구간을 표시 |
| 자동 편집 후보 | 웃음, 평소 대비 채팅 급증, 같은 말의 집단 반복, 감정 반응, 참여자 증가. 다시보기는 방송 전체를 보고 각 순간을 앞뒤 5분·30분의 평소와 비교해 강함·보통·약함과 순위를 매기고 "웃음 7명 (평소 0.6명)"처럼 근거 수치를 보여 줌. 생방송은 채팅이 몰리면 민감한 기준으로 **예비** 후보를 바로 띄우고, 반응 5분 뒤 다시보기와 같은 기준으로 **5분 판정**, 30분 뒤 **확정** |
| 방송 내용 인식 | 다시보기 음성(가장 낮은 화질)이나 NAS 백업 음성을 이 컴퓨터에서 대본으로 만듦. 다시보기는 수집이 끝나면 저절로, 생방송은 판정한 후보 구간만 수집하면서 인식(일반 설정) |
| 영상 재생 | 다시보기 후보나 채팅 한 줄을 누르면 앱 안 영상이 그 시각으로 이동하고, 재생 위치에 맞춰 채팅이 따라감. 영상 아래 이동 버튼과 방향키(5초, Shift 30초)·스페이스(재생)로 조작. 생방송은 수집하는 동안 지금 방송을 채팅 옆에서 재생 |
| 시청자 추천 | 다시보기 아래 댓글에 적힌 시각을 읽어 자동 후보와 따로 표시. 댓글 직접 붙여넣기 지원 |
| 통합 타임라인 | 자동 탐지·시청자 추천·AI 추천을 한 목록에 시간순으로 모음 |
| AI 검토 | 후보마다 "그 장면이 무엇인지" 채팅과 대본으로 짐작한 설명(장면 설명)을 받아 후보 아래에 표시하고, 고른 후보는 **AI 컷 분석**으로 근거가 붙은 편집 구간을 받음. 일반 설정에서 켜면 후보가 나올 때마다 저절로(작업당 요청·비용 한도 안에서), 끄면 버튼으로. 대본은 AI가 앞뒤 맥락으로 잘못 들은 말을 다듬음. 작업마다 맞는 모델(대본 다듬기·장면 설명·컷 분석). Claude·Codex(ChatGPT 로그인, CLI로 실행)·OpenCode(Go 구독·무료 모델, CLI로 실행)·CLIProxyAPI·OpenCodex·OpenAI. 설치된 도구는 앱을 켤 때 자동으로 찾음 |
| MCP 서버 | 수집한 채팅과 후보를 Claude Desktop·Claude Code에서 읽기 전용으로 조회 |
| 내보내기 | 전체 채팅 TXT/JSONL, 후보 TXT/CSV/JSON, 후보별 앞뒤 채팅, 생방송 중간 저장 |
| 저장 목록 정리 | 작업을 목록에서만 숨기고 다시 표시. 채팅과 파일은 그대로 보관 |
| 설정 | 일반 설정(자동으로 할 일과 그 한도, 새 작업 수집 옵션의 기본값), AI 검토의 기본 제공자·작업별 모델, 제공자별 API 키(메모리 또는 이 컴퓨터에 저장), 방송 내용 인식, 백업 묶음 |

후보는 채팅 반응으로 고른 추천입니다. 실제 장면은 영상에서 확인한 뒤 편집 구간을 정하세요.

## 설치와 빌드

지금은 미리 빌드한 실행파일을 배포하지 않으므로 소스에서 빌드합니다. 빌드에만 아래 도구가 필요합니다.

- Go 1.26 이상
- Node.js 20.19 이상 (npm 포함)
- make

```bash
git clone https://github.com/manwol-ryu/momentforge.git
```

```bash
cd momentforge && make build
```

`make build`는 화면(web)을 빌드해 실행파일에 넣고 `bin/momentforge`를 만듭니다. 이 파일 하나만 있으면 되므로 원하는 폴더로 옮겨 써도 됩니다. Go가 PATH에 없으면 Makefile이 `/usr/local/go/bin/go`를 씁니다.

## 실행

```bash
./bin/momentforge
```

로컬 서버를 실행하고 브라우저를 엽니다. `momentforge serve`와 같습니다. 터미널에 주소(기본 `http://127.0.0.1:8765`)와 데이터 폴더의 절대 경로가 표시됩니다. 처음에는 **샘플로 먼저 체험**으로 예시 채팅의 결과 화면을 볼 수 있습니다.

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--port` | `8765` | 사용할 포트. 항상 `127.0.0.1`에만 열립니다 |
| `--data` | `.momentforge` | 데이터 폴더(채팅 DB·내보내기·실행 정보). 상대 경로는 **실행한 현재 폴더** 기준입니다 |
| `--no-browser` | 끔 | 브라우저를 자동으로 열지 않습니다 |

```bash
./bin/momentforge serve --port 8766 --data ~/momentforge-data
```

- 같은 데이터 폴더로 서버를 두 개 띄울 수 없습니다. 다른 프로그램이 포트를 쓰고 있으면 `--port`로 바꾸라는 안내가 나옵니다.
- 종료는 실행한 터미널에서 **Ctrl+C**입니다. 진행 중인 다시보기 수집은 안전한 지점에서 일시정지되어 다음에 **이어받기**로 이어 갈 수 있고, 생방송 수집은 받은 채팅을 저장한 뒤 멈춥니다. 바로 보내던 AI 검토는 멈추고, 접수된 배치는 Anthropic에서 계속 처리됩니다. 브라우저 탭만 닫으면 서버와 수집은 계속됩니다.
- `momentforge version`은 버전을, `momentforge help`는 사용법을 출력합니다.

## 화면 구성

- 왼쪽 **작업 목록**에 저장한 작업이 있고, 열린 작업이 표시됩니다. 위의 **새 작업**으로 처음 화면에 돌아갑니다. 넓은 화면에서는 **작업 목록 접기**로 접을 수 있고(브라우저에 기억), 휴대폰에서는 위쪽 **작업 목록** 버튼으로 엽니다. **목록 정리**에서 모두 숨기거나 다시 표시합니다(채팅과 파일은 지우지 않음). 목록 아래 **설정**으로 설정 화면을 엽니다(접은 막대에서는 맨 아래 아이콘).
- **새 작업** 화면은 **다시보기**, **생방송**, **NAS 백업** 탭으로 나뉩니다. 다른 종류의 주소를 붙여넣으면 맞는 탭으로 옮겨 갑니다. 수집 옵션은 설정의 기본값으로 시작합니다. 오른쪽에는 **최근 작업**(처음이면 사용 순서와 샘플)이 있습니다.
- **설정** 화면은 **AI 검토**, **일반 설정**, **방송 내용 인식**, **백업 묶음** 탭으로 나뉩니다. 오른쪽에 앱 정보(버전, 지원 플랫폼, 데이터 폴더)와 저장 위치가 있습니다. 자세한 내용은 [설정](#설정)을 보세요.
- 작업 화면은 위에 요약 숫자, 가운데에 영상·채팅·반응 타임라인, 오른쪽에 탭(다시보기: 후보, 대본, 댓글, 파일 / 생방송: 후보, 수집 상태, 파일)을 둡니다. AI 검토는 따로 탭이 없고 후보 목록 위의 AI 줄과 후보 아래에 있습니다. 넓은 화면에서는 창 높이에 맞춰 영상과 타임라인이 늘 보이고 오른쪽 탭만 스크롤합니다.
- **수집하고 편집점 찾기**를 누르면 작업이 저장되는 대로 그 작업 화면으로 옮겨 가 진행 상황을 보여 주고, 수집이 끝나면 같은 화면에 후보가 나타납니다.
- 재생 위치는 여러 방법으로 옮깁니다: 후보를 누르면 그 편집 구간부터 재생, **재생 위치 채팅**의 채팅 한 줄을 누르면 그 시각으로 이동, 타임라인을 누르거나 끌기, 영상 아래 **−30초·−5초·재생·+5초·+30초** 버튼, 키보드 **←·→**(5초), **Shift+←·→**(30초), **스페이스**(재생·일시정지). **N**·**P**(또는 타임라인의 **다음 후보**·**이전 후보**)는 재생 위치 다음·이전 후보로 옮깁니다. 키보드 조작은 입력칸이나 탭에 포커스가 없을 때 화면 어디서나 같게 동작하고, 한글 입력 상태에서도 됩니다.
- 긴 방송은 타임라인 위의 **전체·30분·10분·2분**으로 재생 위치 주변을 확대해 붙어 있는 후보를 나눠 볼 수 있습니다. 확대하면 아래 얇은 막대가 지금 보는 구간을 보여 줍니다. 영상이 없는 작업은 그 위치의 앞뒤 채팅을 보여 줍니다.
- 반응 타임라인은 기본으로 **평소 대비** 막대를 보여 줍니다. 그 시각의 평소보다 얼마나 드문 반응인지(점수)가 높이이고, 편집 후보 기준을 넘은 곳은 산호색, 기준은 점선입니다. **채팅 수**로 바꾸면 채팅 건수와 그 시각의 평소 수준 선을 봅니다. 마커 크기는 후보 강도를 따르고, 목록에서 거른 후보는 마커도 숨습니다. 선택은 브라우저에 기억됩니다.

## 다시보기 (VOD)

1. 새 작업의 **다시보기** 탭에서 **치지직 다시보기 주소**에 `https://chzzk.naver.com/video/영상번호`(또는 영상번호만)를 넣습니다.
2. 필요하면 옵션을 고릅니다.
   - **항상 가장 민감하게**: 후보로 삼는 점수 기준을 낮춥니다(생방송은 10초에 채팅 6건부터 판정). 작은 반응도 찾지만 잘못 잡는 후보가 늘 수 있습니다.
   - **영상 댓글의 시청자 추천도 수집**: 댓글에 적힌 시각을 자동 후보와 따로 표시합니다.
3. **수집하고 편집점 찾기**를 누릅니다. 채팅을 모두 받은 뒤 후보를 찾습니다. 긴 방송은 몇 분 걸리며, 중단해도 받은 데까지 저장됩니다.
4. 후보 행에는 타임라인 마커와 같은 **후보 N** 번호, 강도(**강함·보통·약함**)와 순위, 최고점에서 평소보다 튄 수치(예: "웃음 7명 (평소 0.6명)")가 붙습니다. 목록 위에서 **시간순·강한 순**과 **모든 강도·강함·보통만**을 고를 수 있습니다(브라우저에 기억). 후보나 타임라인 마커를 누르면 앱 안 영상이 그 편집 구간부터 재생되고, 판정 근거(많이 나온 문장)와 편집 구간 채팅(`*`는 판정 근거)이 펼쳐집니다. **재생 위치 채팅**은 재생 위치 앞뒤 30초의 채팅이며, 채팅 한 줄을 누르면 영상이 그 시각으로 갑니다. **따라가기**를 켜면 재생에 맞춰 채팅이 함께 움직입니다. 작성자는 가명 키의 앞 네 글자를 색 태그로 보여 주고, 이모티콘 코드는 이름이 적힌 칩으로 보여 줍니다.
5. 끝나지 않은 작업은 **이어받기**로 이어서 받고, 저장한 채팅은 **다시 분석**으로 옵션을 바꿔 다시 분석합니다.
6. **설정 › 일반 설정**에 따라 수집이 끝난 뒤 저절로 이어서 합니다: **다시보기 방송 내용 인식**(기본 켜짐)이면 방송 음성을 받아 대본을 만들고, **AI 검토 자동 실행**(기본 꺼짐)을 켰으면 대본을 다듬은 뒤 모든 후보의 장면 설명을 받습니다. 작업 카드에 단계(방송 음성 받기 → 방송 내용 인식 → AI 대본 다듬기 → AI 장면 설명)가 차례로 보이고, 못 한 단계는 이유와 함께 경고로 남습니다. 끈 단계는 대본 탭의 **방송 내용 인식**, 후보 목록 위의 **AI 장면 설명 받기**로 할 수 있습니다.

다시보기는 채팅을 다 받은 뒤 **방송 전체**를 봅니다. 10초(천천히 쌓이는 반응은 20초)마다 웃음·감정·같은 문장을 쓴 사람 수, 채팅 수, 채팅한 사람 수를 그 시각 앞뒤 5분과 30분의 평소 값(둘 중 조용한 쪽)과 비교해, 평소에 그만큼 나올 확률이 얼마나 낮은지를 점수로 매깁니다. 고정 건수나 "평소의 몇 배"가 아니므로 시청자 수, 방송 시간대, 방송 안의 붐빔과 한산함이 달라도 그 시간대치고 드문 반응을 고르고, 방송 시작 직후도 바로 판정합니다. 점수가 높은 순서로 순위를, 점수와 순위로 **강함·보통·약함**을 붙입니다. 약함은 우연히 몰린 반응일 수도 있는 참고 후보입니다. 영상은 치지직 CDN의 공개 스트림을 브라우저가 바로 재생하며, 영상 파일을 저장하지 않습니다.

로그인이 필요한 다시보기는 수집할 수 없습니다([보류한 기능](#보류한-기능과-아직-없는-기능)).

## 생방송 (LIVE)

1. 새 작업의 **생방송** 탭에서 **치지직 생방송 주소**에 `https://chzzk.naver.com/live/채널ID`를 넣고 **방송 확인**을 누릅니다. 제목, 방송 중 여부, 시청자 수가 보입니다.
2. 옵션을 고르고 **수집 시작**을 누릅니다.
   - **항상 가장 민감하게**: 다시보기와 같습니다.
   - **시청자 수 변화 보정**: 공개 웹 시청자 수를 함께 기록합니다. 방송 30분 이후의 5분 평균을 기준으로 잡고, 기준보다 10% 줄어든 상태가 2분 이상 이어서 확인되면 그때부터 평소 채팅량 기준을 다시 학습합니다.
3. 처음 3분 동안 채널을 지켜본 뒤 판정을 시작합니다. 받은 채팅은 평소 대화까지 모두 저장하고, 화면에는 실시간 채팅·반응 타임라인·편집 후보가 함께 보입니다. 후보는 세 단계로 바뀝니다([생방송 후보의 단계](#생방송-후보의-단계)).
   - **예비**(점선): 채팅이 몰리면 평소 기준의 3분의 2로 민감하게 바로 띄웁니다. 반응이 끝나고 30초 뒤 채팅까지 받으면 "5분 판정 대기"가 됩니다. 타임라인 마커도 흐리게 보입니다.
   - **5분 판정**(선): 반응 뒤 5분의 채팅까지 보고 다시보기와 같은 방송 전체 기준(앞뒤 5분·30분의 평소와 비교)으로 판정합니다. 강도·순위·평소 대비 수치가 붙고, 겹치던 예비 후보는 이 후보로 바뀝니다(고르고 있었다면 선택도 옮겨 감). 판정에서 빠진 예비 후보는 목록에서 사라집니다.
   - **확정**(채움): 반응 뒤 30분의 채팅까지 보고, 또는 수집을 마칠 때 확정하며 그 뒤로 바뀌지 않습니다. 그 전의 5분 판정 후보는 범위가 조금 바뀌거나 빠질 수 있습니다.
4. 수집하는 동안 **현재까지 저장**은 그 시점의 채팅과 후보를 고정된 파일 묶음으로 저장합니다(**파일** 탭). 연결 복구 횟수, 못 받은 구간, 판정 기준은 **수집 상태** 탭에 있습니다.
5. **수집 중단**은 남은 채팅을 저장하고 마감합니다. 멈춘 동안의 채팅은 받을 수 없어서 누르면 한 번 더 묻습니다(**계속 수집** | **수집 중단**). 같은 방송이 아직 진행 중이면 **이어 기록**으로 같은 기록에 이어 받습니다.
6. **설정 › 일반 설정**의 **생방송 음성도 받아 후보 구간 인식**(기본 켜짐)이면 수집하는 동안 방송 음성을 가장 낮은 화질로 받아 최근 25분만 두고, 5분 판정한 후보의 편집 구간과 앞뒤 1분을 이 컴퓨터에서 인식합니다. 후보를 고르면 **편집 구간 방송 내용**으로 보이고, 수집을 마치면 받은 음성을 지웁니다. **AI 검토 자동 실행**을 켰으면 판정한 후보마다 대본을 다듬고 장면 설명을 받습니다(약 2분씩 모아서). 상태는 **수집 상태** 탭의 **방송 음성**·**자동 작업**에 있습니다([생방송 기록의 AI 검토](#생방송-기록의-ai-검토)).

- 생방송 수집은 한 번에 하나입니다. 다시보기 수집과는 동시에 할 수 있습니다.
- 수집을 시작하기 전 채팅이나 연결이 끊긴 동안의 채팅은 받을 수 없습니다. 끊긴 구간은 타임라인에 빗금으로 표시하고 평소 채팅량 학습에서 뺍니다. 방송 중간에 시작한 기록은 타임라인을 **수집한 구간**부터 보여 주고, **방송 전체**로 바꿀 수 있습니다.
- 실시간 채팅을 위로 올려 읽는 동안에는 목록이 멈추고, 그사이 들어온 채팅 수를 **새 채팅 N건, 최신 채팅으로**에 보여 줍니다.
- 연결 전에 보냈거나 분석이 지난 뒤 도착한 채팅은 "늦게 받음"으로 저장합니다. 예비 후보 계산에는 넣지 않고, 저장된 채팅을 다시 읽는 5분 판정·확정에는 넣습니다. 재연결 때 다시 온 채팅은 버립니다. 이 단계 판정 전(규칙 3.1.0 전)에 시작한 기록은 예전처럼 반응이 끝나고 뒤 채팅까지 받으면 한 번에 확정합니다.
- 시각은 방송 시작 후 경과 시간입니다. 방송 시작 시각을 받지 못하면 수집 시작 후 경과 시간으로 표시합니다.
- 앱을 다시 실행해도 저절로 다시 접속하지 않습니다. 같은 방송이면 **이어 기록**을 누르세요. 컴퓨터가 꺼지거나 잠자기 상태인 동안에는 수집할 수 없습니다.
- 수집하는 동안 작업 화면의 **영상** 카드에서 지금 방송을 볼 수 있습니다. 재생을 눌러야 영상을 받기 시작하고, 멈추면 받기도 멈춥니다. 영상은 치지직 CDN의 공개 스트림을 브라우저가 바로 재생하며 저장하지 않습니다.
- 영상은 채팅보다 10초 넘게 늦을 수 있습니다(HLS 방식의 지연). 영상 위치와 채팅 시각은 연결하지 않으므로, 후보의 정확한 장면은 나중에 다시보기에서 확인하세요.
- 방송이 끝났거나, 연령 제한·유료 방송이거나, 재생 주소를 받지 못하면 영상 카드에 이유와 **다시 불러오기**가 나옵니다. 이때는 위의 **치지직에서 열기**로 보세요. 수집을 멈춘 기록은 영상을 불러오지 않습니다(그때의 방송이 아니라 지금 방송이 나오기 때문).

### 생방송 후보의 단계

생방송은 뒤의 채팅을 아직 받지 못했으므로, 그 순간이 그 시간대치고 드문 반응이었는지 바로 알 수 없습니다. 그래서 빨리 보이는 것과 정확한 것을 나눕니다(규칙 3.1.0).

| 단계 | 언제 | 기준 |
|---|---|---|
| 예비 | 반응하는 동안부터 | 지나간 채팅만 보는 증분 판정. 판정 시작 기준을 평소의 3분의 2(최근 2시간 평소 채팅의 2.5배 또는 최근 15분 평소 작성자의 3.35배)로 낮춰 놓치지 않게 먼저 띄움 |
| 5분 판정 | 반응 뒤 5분 | 분석이 1분 나아갈 때마다 저장된 최근 70분 채팅을 다시보기와 같은 방송 전체 분석으로 다시 봄. 앞뒤 5분의 평소와 비교가 끝난 순간 |
| 확정 | 반응 뒤 30분, 또는 수집을 마칠 때 | 앞뒤 30분의 흐름까지 비교가 끝나 다시보기 결과와 같아지는 순간. 그 뒤로 바뀌지 않음 |

- 5분 판정 후보는 같은 순간이면 번호가 이어지고(겹치는 범위로 찾음), 다음 판정에서 기준을 넘지 못하면 빠졌다가 다시 넘으면 같은 번호로 돌아옵니다.
- AI 장면 설명·컷 분석과 생방송 음성 인식은 5분 판정한 후보부터 합니다. 예비 후보는 아직 범위와 판정이 바뀔 수 있어 보내지 않습니다.
- 내보내는 파일(현재까지 저장, 최종 저장)에는 판정에서 빠진 후보를 넣지 않습니다.

## NAS 백업 불러오기

chzzk-automation이 NAS에 백업한 다시보기(`YY/MM/YY_MM_DD 제목.{mp4,m4a,chat.jsonl,chat.txt}`)를 치지직에 다시 접속하지 않고 불러옵니다. NAS 공유 폴더를 Finder로 연결해 두면 됩니다.

1. 새 작업의 **NAS 백업** 탭에 월 폴더 경로(예: `/Volumes/공유/채널/26/10`)를 넣고 **폴더 읽기**를 누릅니다. 폴더의 `.chat.jsonl`마다 방송 하나가 날짜·채팅·음성·영상 크기와 함께 나오고, 이미 불러온 방송은 **열기**로 바뀝니다.
2. **불러오기**를 누르면 채팅을 읽어 새 작업을 만들고 편집 후보를 찾은 뒤, **방송 내용 인식(전사)까지**가 켜져 있으면 같은 이름의 `.m4a`를 이 컴퓨터에서 인식합니다. 끝나면 작업 화면으로 옮겨 갑니다. 파일은 복사하지 않고 그 자리에서 읽으며, 영상(`.mp4`)이 있으면 작업 화면의 영상 카드가 그 파일을 재생합니다(이 서버가 같은 컴퓨터 안에서만 전달).
3. 백업 채팅의 **후원·구독**도 함께 들어옵니다. 재생 위치 채팅에 💰 금액, ⭐ 구독 개월로 표시되고, 내보내기 TXT·JSONL과 AI 컷 분석의 근거에도 포함됩니다. 봇이 가린 채팅은 흐리게 보입니다. 후원 메시지의 글은 시청자 채팅으로 세고, 구독 알림과 봇이 가린 채팅은 반응으로 세지 않습니다.
4. 작성자 ID·닉네임·이모티콘 주소는 저장하지 않습니다. 작성자는 다른 수집과 같이 세션별 가명 키가 됩니다([PRIVACY](PRIVACY.md)).

### 방송 내용 인식 (전사)

방송자가 한 말을 글로 바꿔 **대본** 탭에 두고(발언을 누르면 그 시각으로 이동, 10분 단위로 넘기며 찾기), SRT·VTT로 내보내며(파일 탭), AI 장면 설명과 컷 분석이 발언을 근거로 씁니다. 인식은 **이 컴퓨터에서만** 합니다.

| 엔진 | 조건 | 비고 |
|---|---|---|
| **Apple 음성 인식** (기본) | macOS 26 이상 | 실행파일에 든 작은 도우미가 macOS의 `SpeechAnalyzer`를 부릅니다. 한국어 모델은 macOS가 처음 한 번 내려받아 관리합니다. Apple M4에서 7시간 44분 방송이 약 4~5분(실시간의 140~190배) |
| **whisper.cpp** (선택) | 사용자가 whisper.cpp의 `whisper-cli`와 ggml 모델 파일(한국어는 `large-v3-turbo` 또는 `large-v3-turbo-q5_0` 권장)을 설치하고 **설정 → 방송 내용 인식**에 두 파일의 전체 경로를 적음 | 모든 OS. MomentForge가 설치·다운로드하지는 않습니다. 입력이 WAV가 아니면 ffmpeg(설치되어 있을 때) 또는 macOS 내장 `afconvert`로 16kHz WAV를 만들어 넘기므로, 다른 OS에서 m4a·mp4를 전사하려면 ffmpeg가 필요합니다 |

대본 탭의 **다시 인식**으로 새 전사를 만들 수 있습니다(이전 전사는 남지만 화면과 분석은 최신 것을 씁니다). 노래 구간이나 겹치는 말은 잘못 들릴 수 있고, 발언은 늘 "음성 인식 결과"로 다룹니다.

**AI로 대본 다듬기**: **AI 검토 자동 실행**과 **AI로 대본 다듬기**(일반 설정)가 켜져 있으면, 새로 인식한 대본을 AI가 앞뒤 세 줄의 맥락, 방송 제목, 그때 채팅에서 시청자가 많이 쓴 낱말과 함께 읽고 **분명히 잘못 들은 낱말만** 고칩니다(사투리·말버릇·욕설은 그대로, 문장을 새로 쓰지 않음). 바뀐 정도가 큰 답은 받아들이지 않고, 고친 줄에는 **다듬음** 표시가 붙으며 마우스를 올리면 인식한 원문이 보입니다. 대본 탭 위에 "AI가 앞뒤 맥락으로 N줄을 다듬었습니다"가 나옵니다. 장면 설명은 다듬은 대본으로 받습니다.

음성은 네 곳에서 옵니다.

| 작업 | 음성 | 하는 일 |
|---|---|---|
| NAS 백업 | 연결된 `.m4a`(없으면 `.mp4`) | 그 자리에서 읽어 인식 |
| 치지직 다시보기 | 공개 재생 주소의 **가장 낮은 화질(오디오 전용이 있으면 그것)** | 데이터 폴더 `runtime/audio/`에 받아 인식하고, 끝나면(실패해도) 지웁니다. 받는 동안 작업 카드에 "방송 음성 받기" 진행률이 보입니다. **다시보기 방송 내용 인식**(일반 설정, 기본 켜짐)이면 수집이 끝난 뒤 저절로 합니다 |
| 치지직 생방송 | 수집하는 동안 지금 방송의 **가장 낮은 화질** | **생방송 음성도 받아 후보 구간 인식**(일반 설정, 기본 켜짐)이면 조각마다 `runtime/audio/`에 받아 최근 25분만 두고, 5분 판정한 후보의 편집 구간과 앞뒤 1분만 인식해 그 기록의 대본에 더합니다. 음성이 아직 오지 않은 후보는 최대 3분 기다립니다. 수집을 마치면 지웁니다 |
| 자막 파일 | 가진 SRT·VTT 파일 | 대본 탭 **자막 파일 넣기**에 파일과 시간 오프셋(초; 자막이 영상보다 3초 늦으면 -3)을 넣으면 인식 없이 발언이 됩니다. 파일의 화자 이름은 ‘방송자’·‘게스트 1’ 같은 역할명으로 바뀌고 파일은 저장하지 않습니다 |

**설정 → 방송 내용 인식**에서 등록된 엔진마다 준비 상태와 준비 방법을 보고, 기본 엔진(자동 또는 특정 엔진)과 whisper.cpp 경로를 정합니다. 고른 엔진이 준비되지 않았으면 준비된 다른 엔진을 씁니다.

## 시청자 추천 (영상 댓글)

다시보기 아래 공개 댓글에 시청자가 적은 시각(예: `1:23 웃긴 장면`, `12:00~13:30`)을 읽어 **시청자 추천**으로 표시합니다. 방송 당시 채팅과 섞지 않고 출처를 따로 둡니다.

- 다시보기 작업 화면 **댓글** 탭의 **영상 댓글 읽기**(다시 읽을 때는 **영상 댓글 다시 읽기**)로 댓글을 받습니다.
- 댓글을 복사해 왔다면 **시각이 적힌 댓글 직접 붙여넣기**(12,000자 이하) → **붙여넣은 추천 저장**을 씁니다.
- 채팅 없이 댓글만 보려면 새 작업의 다시보기 탭에서 **댓글만 수집**을 누릅니다. 나중에 같은 작업에서 **채팅 수집**을 누르면 채팅을 이어 받아 한 작업에 모입니다.
- 시계 시각이나 상대 시각처럼 보이는 표기는 "확인이 필요한 시각"으로 따로 보여 줍니다.
- 댓글을 읽지 못해도 채팅 수집은 그대로 진행되고 경고만 표시합니다.

## 통합 타임라인

작업 화면 **후보** 탭의 편집 후보 목록은 세 출처를 영상 시각 순서로 함께 보여 줍니다(생방송 작업은 자동 탐지와 AI 추천 두 출처). 출처마다 색이 다르며(자동 탐지 산호색, 시청자 추천 청록, AI 추천 보라) 타임라인 마커와 같습니다.

| 출처 | 내용 |
|---|---|
| 자동 탐지 | 채팅 통계 규칙이 찾은 후보와 판정 이유, 강도·순위, 평소 대비 수치 |
| 시청자 추천 | 영상 댓글에 적힌 시각과 댓글 내용 |
| AI 추천 | AI 검토가 후보 밖에서 새로 찾은 구간, 이유, 중요도, 판단 한계. 고른 후보를 설명한 결과는 따로 행을 만들지 않고 그 후보 아래 **AI 설명**으로 붙습니다 |

**후보 출처**로 출처를 골라 볼 수 있고, 후보를 누르면 영상이 그 구간부터 재생되며, 후보마다 **치지직에서 열기**가 있고, 고른 후보에는 **AI 컷 분석**이 나옵니다. 후보 아래의 AI 설명·컷 분석은 고르지 않은 후보에서는 한 줄로 줄고, 후보를 고르면 전체가 펼쳐집니다. 다시 분석해 후보 번호가 바뀌어도 AI 결과는 시간으로 같은 장면의 후보를 찾아 그 아래에 붙고(겹치는 후보가 없으면 따로 한 줄), 그 결과의 **다시 분석**은 앞 버전과 메모를 이어 갑니다. 다시보기는 출처가 바뀔 때마다 통합 타임라인 파일(`timeline/`의 TXT·CSV·JSON, 파일 탭의 **모든 출처 편집 후보**)을 다시 만듭니다.

**파일** 탭은 파일을 묶음으로 보여 줍니다: 컷 확정본(편집 프로그램·editnest용), 편집 후보(모든 출처·자동 탐지), 채팅, 시청자 추천(영상 댓글), AI 검토, 컷 분석(장면 시각과 버전마다), 대본, 수집 기록. 새 버전으로 바뀐 이전 컷 분석 파일은 맨 아래 **이전 컷 분석 파일**에 접혀 있습니다.

## 설정

왼쪽 작업 목록 아래 **설정**에서 정합니다. 처음 열면 **일반 설정** 탭이 보입니다. **AI 검토** 탭에서 **설정할 AI 제공자**를 고르면 그 아래에 그 제공자의 모델·키(CLIProxyAPI·OpenCodex는 주소와 실행 상태도) 칸이 나옵니다. 고르기만 해서는 기본 제공자가 바뀌지 않고, 그 칸의 **기본 제공자로 쓰기**를 눌러야 바뀝니다(기본 제공자에는 **기본** 표시). 기본값은 **기본값 저장**을 눌러야 저장되고, API 키는 제공자마다 **키 저장**으로 따로 저장합니다.

| 탭 | 항목 | 동작 |
|---|---|---|
| 일반 설정 | 다시보기 방송 내용 인식 (기본 켜짐) | 다시보기 수집이 끝나면 방송 음성을 받아 이 컴퓨터에서 대본을 만듭니다. 대본이 이미 있으면 건너뜁니다 |
| 일반 설정 | 생방송 음성도 받아 후보 구간 인식 (기본 켜짐) | 생방송을 수집하는 동안 음성을 가장 낮은 화질로 받아 최근 25분만 두고, 5분 판정한 후보 구간을 인식합니다. 수집을 마치면 지웁니다 |
| 일반 설정 | AI 검토 자동 실행 (기본 꺼짐) | 켜면 보내는 것·보내지 않는 것·한도를 보여 주고 **동의하고 켜기**를 눌러야 켜집니다(**켜지 않기**로 그만둠). 켜 두면 후보가 나올 때마다 묻지 않고 장면 설명을 받습니다 |
| 일반 설정 | AI로 대본 다듬기 (기본 켜짐) | 자동 실행이 켜졌을 때, 새로 인식한 대본을 장면 설명 전에 다듬습니다 |
| 일반 설정 | 작업마다 최대 요청 (기본 60회, 1~500), 작업마다 비용 한도 (기본 3달러) | 한 작업이 자동으로 보낼 수 있는 양입니다. 비용 한도는 가격을 아는 모델(Claude)에만 적용됩니다. 닿으면 강한 후보부터 보낸 데까지 멈추고 작업 경고로 알립니다 |
| 일반 설정 | 항상 가장 민감하게, 영상 댓글의 시청자 추천도 수집, 시청자 수 변화 보정 | 새 작업의 다시보기·생방송 양식이 이 값으로 시작합니다. 양식에서 바꾼 값은 그 작업에만 씁니다 |
| AI 검토 | 기본 AI 제공자 | 제공자 칸의 **기본 제공자로 쓰기**로 정합니다. 자동 AI 검토, **AI 장면 설명 받기**, **AI 컷 분석**이 모두 이 제공자로 보냅니다 |
| AI 검토 | 제공자별 기본 모델 ID | 작업별 모델을 비워 두고 제공자도 권하는 모델이 없을 때 쓰는 모델입니다. 비우면 제공자의 기본 모델을 씁니다. 키가 있으면 **쓸 수 있는 모델 불러오기**로 고를 수 있습니다 |
| AI 검토 | 작업별 모델 | **대본 다듬기**(요청이 많고 짧아 빠르고 싼 모델), **장면 설명**(채팅과 발언을 함께 읽는 균형 잡힌 모델), **컷 분석**(여러 단계를 추론하는 가장 강한 모델)마다 모델 ID를 정합니다. 비우면 제공자가 그 작업에 권하는 모델(Claude: `claude-haiku-5-5`·`claude-sonnet-5-5`·`claude-opus-5-5`), 권하는 모델이 없으면 위의 기본 모델입니다 |

| AI 검토 | CLIProxyAPI 실행 상태 | 실행 중·꺼짐·설치되지 않음과 **CLIProxyAPI 켜기**·**CLIProxyAPI 끄기**, **상태 다시 확인**, 대시보드가 켜져 있으면 **CLIProxyAPI 대시보드 열기** |
| AI 검토 | OpenCodex 주소 | OpenCodex의 OpenAI 호환 주소. 비우면 실행 중인 OpenCodex의 포트, 없으면 OpenCodex 설정의 포트(없으면 `http://127.0.0.1:10100/v1`) |
| AI 검토 | OpenCodex 실행 상태 | 실행 중·꺼짐·설치되지 않음과 **OpenCodex 켜기**(`ocx start`)·**OpenCodex 끄기**(`ocx stop`), **상태 다시 확인**, 실행 중이면 **OpenCodex 대시보드 열기** |
| AI 검토 | 컷 분석의 검색 예산 | 후보당 검색 단계(기본 4회, 0이면 검색 없음)와 검색으로 더 보내는 글(기본 80KB), **검색 결과를 보내기 전에 매번 확인**(기본 꺼짐) |
| 방송 내용 인식 | 엔진과 프로그램·모델 경로 | [방송 내용 인식](#방송-내용-인식-전사)을 보세요 |

- 기본값은 데이터 폴더의 `settings.env`에 씁니다. 비밀이 아닌 값만 있고, `KEY=값` 형식이라 직접 고쳐도 됩니다(앱을 다시 실행하면 읽음).
- API 키는 메모리에 둡니다. **이 컴퓨터에도 저장**을 고르고 저장한 키만 데이터 폴더의 `.env`에 평문으로 남아 다음 실행에도 쓰입니다. 자세한 규칙은 [AI 검토](#제공자와-로그인)를 보세요.

- 탐지 임계값은 설정에서 바꾸지 않습니다. 같은 채팅이면 같은 후보가 나오도록 규칙 버전과 함께 코드에서 관리합니다.

## AI 검토 (선택)

AI 검토는 후보 앞뒤의 채팅과 그 구간의 방송 대본을 AI에 보내 **그 장면이 어떤 내용인지**(방송자가 무엇을 했고 시청자가 무엇에 반응했는지, 편집할 가치가 있는지) 설명을 받는 선택 기능입니다. 따로 탭이 없고, 작업 화면 **후보** 탭의 목록 위 **AI 줄**과 각 후보 아래에 있습니다. AI는 영상을 보지 않으므로 설명은 짐작이며, 단정할 수 없는 점은 **판단 한계**에 적습니다. 키를 넣지 않아도 수집·자동 후보·방송 내용 인식은 모두 동작합니다.

- **자동으로**: **설정 › 일반 설정**에서 **AI 검토 자동 실행**을 켜면(보내는 것과 한도에 동의), 다시보기 수집·NAS 백업 불러오기·다시 분석이 끝난 뒤, 생방송은 후보를 5분 판정할 때마다, 아직 설명이 없는 후보의 장면 설명을 받습니다. 대본이 새로 생겼으면 먼저 AI로 다듬습니다. 강한 후보부터, 작업마다 정한 요청·비용 한도 안에서만 보냅니다. AI 줄에 "AI 검토 자동 실행 중"과 제공자·모델이 보입니다.
- **남은 후보**: 자동 실행이 켜져 있어도 보내다 중단됐거나(앱을 다시 실행하는 등) 한도에 닿아 설명이 없는 후보가 남으면, AI 줄에 "설명이 없는 후보 N개"와 **남은 후보 설명 받기**가 나옵니다. 누르면 그 후보만 같은 한도 안에서 보냅니다. 수집 중인 생방송은 자동 작업이 이어서 가져가므로 나오지 않습니다.
- **직접**: 자동 실행을 껐으면 AI 줄의 **AI 장면 설명 받기**를 누릅니다. 무엇을 어디로 보내는지와 한도를 한 번 더 묻고(**보내지 않기** | **AI 장면 설명 받기**), 그 작업 하나에 자동 실행과 같은 일을 합니다.
- 보내는 동안 AI 줄에 진행(요청 수, 토큰, 비용)과 **AI 작업 중단**이 보입니다. 결과는 후보마다 그 아래 **AI 설명**(장면 한 줄, 설명, 중요도, AI가 잡은 구간과 **이 구간 재생**, 판단 한계)으로 붙고, 후보 밖에서 새로 찾은 장면은 **AI 추천** 행으로 들어갑니다. 고르지 않은 후보에서는 한 줄로 줄어 있습니다.
- 다시 분석해 후보가 바뀌어도 이미 설명한 장면은 다시 보내지 않습니다(시간으로 같은 장면을 찾아 붙임). 같은 내용을 이미 끝까지 실행했다면 다시 보내지 않고 그 결과를 씁니다.
- 샘플은 저절로 보내지 않고, 직접 누르면 보내 흐름을 볼 수 있습니다.

### 컷 분석 (2세대)

후보를 고르면 그 아래에 **AI 컷 분석** 버튼이 나옵니다. 누르면 그 후보 하나에 네 단계를 차례로 보내 **근거가 붙은 편집 구간**을 받습니다(자동 실행을 끈 상태면 보낼 것과 제공자·모델을 한 번 더 묻고, 설정의 **컷 분석** 작업 모델로 보냄). 단계는 원인 분석(무엇에 반응했는지, 원인 후보 여러 개와 지지·반대 근거) → 편집 구간 계획(필수 맥락, 경계 후보 짧게·맥락·전체, 결말 상태) → 클립만 보는 검수 → 원본 비교 검수. 검수에 걸리면 이유를 넣어 한 번 다시 계획합니다. AI는 시각을 쓰지 않고 발언·채팅 ID로 경계를 말하며, 앱이 시각을 계산합니다: 발언은 시작 0.3초 전부터 끝 0.5초 뒤까지, 채팅은 6초 앞부터 3초 뒤까지이고 그 시각이 발언 중간이면 그 발언의 처음·끝으로 옮깁니다(옮긴 이유는 `plan.json`의 `adjustments`). 결과는 후보 아래 **AI 컷 분석** 상자와 **파일** 탭의 `cuts/`(plan.json, 구간 CSV, EDL)에 들어갑니다.

분석에는 자동 탐지가 잰 반응(반응 구간, 최고점, 강도, 평소 대비 수치)과 5초 칸 반응 곡선(채팅 수, 작성자 수, 같은 반응을 보인 작성자 수, 평소 수준)이 함께 가서 AI가 반응이 오르고 잦아드는 곳을 보고 시작과 끝을 정합니다. 채팅이 많은 구간은 반응 구간의 채팅을 먼저 담고 넣지 못한 채팅 수를 알려 주며, 플랫폼이 가린 채팅은 보내지 않고 후원·구독 알림은 일반 채팅과 구분합니다. 검색은 찾는 시각에 가까운 발언·채팅부터 가져옵니다. 후보 하나의 분석이 실패해도 나머지 후보는 계속 분석하고, 실패한 후보와 이유를 실행 기록에 남깁니다.

**결과 상자**: 반응 대상, 원인(가장 유력한 것과 대안들)과 각각의 **근거·반대 근거 버튼**(누르면 그 시각으로 이동, 발언은 발언 시작), **이야기 기원**·**사건 시작**·**필수 맥락** 버튼, **구간**(경계 후보 **짧게 | 맥락 | 전체** 전환, 타임라인 아래쪽 보라 띠가 함께 바뀜, 구간 이어 재생), 종료 이유와 결말 상태, **검수**(클립만 보기·원본 비교 통과·실패와 "검수 답 보기": 무엇을·조건·결과·'아까'가 가리키는 것·왜 반응), 검수에 걸린 이유(빨간 줄), 미확정 질문이 차례로 보입니다.

**메모와 다시 분석**: **메모 추가**로 고칠 점(예: "두 번째 시도라 앞선 약속과 연결하면 안 됨")을 남기고 결과 상자의 **다시 분석**을 누르면 그 후보를 바로 다시 분석합니다. 그 후보의 모든 버전에 남긴 메모가 계획 단계에 함께 가고, 결과는 **새 버전**(v2, v3…)으로 저장됩니다. 분석하는 동안 버튼 자리에 "AI 컷 분석 중 (n/m회)"가 보입니다.

**컷 확정**: 지금 보는 경계 후보(짧게·맥락·전체)로 그 버전을 확정합니다. 확정한 버전은 새 분석이 와도 그대로 남고, 새 버전은 그 옆에 "확정본 vN 유지"로 보입니다. 다른 버전을 확정하면 앞 확정은 풀리고, **확정 취소**도 있습니다. 확정한 컷은 **파일** 탭의 **컷 확정본** 세 파일(`cuts/confirmed.*`)에 모입니다:

| 파일 | 쓰는 곳 |
|---|---|
| `confirmed.edl` | Premiere Pro·DaVinci Resolve의 EDL 가져오기(CMX 3600, 30fps 기준 시각, 구간을 시간순으로 이어 붙인 가편집) |
| `confirmed.csv` | 표 계산기, 다른 도구 (계획 ID·버전·경계 후보·역할·시작·끝·반응 대상) |
| `confirmed.editnest.json` | editnest **구간 받기** (아래) |

**editnest에서 받기**: editnest의 **구간 받기** 화면에는 EDL·CSV를 읽는 버튼이 없고, **타임라인 메모**에서 불러온 구간을 가져오는 버튼이 있습니다. 그래서 확정본을 editnest 타임라인 메모 형식으로도 씁니다.

1. editnest **타임라인 메모**에서 같은 영상을 엽니다(NAS 백업 영상이면 같은 파일 이름).
2. **JSON 불러오기**로 `confirmed.editnest.json`을 고릅니다. 이 영상에 이미 적어 둔 메모는 **이 파일의 구간으로 바뀝니다**(타임라인 메모의 실행 취소로 되돌릴 수 있음). 기존 메모를 지키려면 먼저 **JSON 저장**으로 백업하세요.
3. editnest **구간 받기**에서 같은 영상을 열고 **타임라인 메모에서 가져오기**를 누르면 구간이 들어오고, **받기**·**모두 받기**로 자릅니다.

EDL을 editnest가 직접 읽게 하려면 editnest 쪽 변경이 필요합니다(이 저장소에서는 바꾸지 않음). 설계와 다음 단계는 [docs/AI-CUT-ANALYSIS.md](docs/AI-CUT-ANALYSIS.md)에 있습니다.

**앞선 맥락 검색**: 원인 분석이 "아까", "약속", "그거"처럼 읽은 범위 밖을 가리키는 것을 만나면, 앱이 **그 방송 안의** 발언과 채팅을 검색해(낱말 찾기, 특정 시각 앞뒤 읽기, 구간 읽기, 채팅량 훑기) 찾은 것을 보태 분석을 다시 합니다. 얼마나 더 보낼 수 있는지는 **설정 › AI 검토 › 컷 분석의 검색 예산**(기본 후보당 4단계·80KB, 0이면 검색 없음)으로 정합니다. 같은 곳의 **검색 결과를 보내기 전에 매번 확인**을 켜면 검색이 찾은 발언·채팅을 보내기 전에 후보 목록 위 AI 줄에 멈추고 보여 주며, **보내고 계속** 또는 **보내지 않고 계속**(처음 범위만으로 계획)을 고릅니다. 끄면 상한 안에서 바로 보내고, 무엇을 더 보냈는지는 실행 기록(`sent_log`)에 단계별로 남습니다. 컷 상자에 "검색 N단계로 근거 M건을 더 읽음"과 찾아낸 **이야기 시작** 시각이 표시됩니다.

컷 분석은 후보 단위이고, 읽는 자료는 편집 구간 앞뒤 1분의 발언과 채팅에 검색으로 찾은 것을 더한 것입니다. 발언은 방송 내용 인식(위 절)이나 자막 파일로 만든 대본에서 오고, 대본이 없는 작업은 채팅만으로 분석합니다. 샘플에는 가짜 발언이 들어 있지만 AI로 보내지 않습니다.

장면 설명은 후보가 있는 10분 단위 구간(앞뒤 30초 겹침)마다 10KB 이하 요청 하나로, 한 계획에 최대 20요청까지 보냅니다. 채팅과 대본이 한 요청에 다 들어가지 않으면 후보의 편집 구간 안(발언 먼저, 구간 가운데에 가까운 순), 그다음 가까운 바깥 순으로 담고 나머지는 보내지 않습니다(실행 기록의 `context_trimmed`). 후보 없이 채팅만 담은 요청은 만들지 않습니다. 앱을 다시 실행해 끊긴 실행은 "일부 완료"로 닫고, 그때까지 받은 결과로 파일 탭의 AI 검토 파일과 통합 타임라인 파일을 씁니다. 사용 한도(429)나 서버 오류는 잠시 뒤 다시 보내지만, 보냈는지 알 수 없는 요청은 중복 비용을 막으려고 다시 보내지 않습니다. AI 답은 입력에 있는 근거만 인용하고 구간 안의 시각만 쓴 추천만 받아들입니다.

### 생방송 기록의 AI 검토

생방송 작업에서도 같은 제공자·모델·한도를 쓰며, 수집 중에도 됩니다. 다음만 다릅니다.

- 자동 실행과 **AI 장면 설명 받기**는 **5분 판정**·**확정** 후보만 보냅니다. **예비** 후보는 범위와 판정이 아직 바뀔 수 있어 보내지 않고, **AI 컷 분석** 버튼도 판정한 후보에만 나옵니다. 이 단계 판정 전에 시작한 기록은 확정되었거나 부분 문맥으로 마감된 후보를 보냅니다.
- 자동 실행은 판정한 후보를 약 2분씩 모아 한 번에 보냅니다. 그 후보의 음성이 아직 인식되지 않았으면(생방송 음성 인식이 켜져 있을 때) 최대 3분 기다렸다가 대본과 함께 보냅니다.
- 보낼 때 그 순간까지 저장된 채팅만 보내고, 그 뒤에 받은 채팅은 보내지 않습니다. "늦게 받음" 채팅도 그 시각의 채팅이라 함께 보냅니다.
- 결과는 **후보** 탭(후보 아래 AI 설명, 출처 **AI 추천**)과 반응 타임라인의 마커로 보이고, **파일** 탭에서 AI 추천 TXT·JSON을 받을 수 있습니다. 판정에서 빠진 후보의 설명은 같은 시간의 후보가 있으면 그 아래로, 없으면 AI 추천 한 줄로 남습니다.
- 자동 작업을 못 한 이유(한도, 키, 음성 인식 엔진)는 **수집 상태** 탭의 **자동 작업**에 보입니다.

### 제공자와 로그인

| 제공자 | 로그인 | 기본 모델 | 작업별 권하는 모델 | 모델 목록 | 비용 한도 |
|---|---|---|---|---|---|
| **Claude (Anthropic)** — 기본 | API 키. 설정에서 **키 저장**, 또는 시작할 때 환경변수 `ANTHROPIC_API_KEY` | `claude-opus-5-5` | 대본 다듬기 `claude-haiku-5-5`, 장면 설명 `claude-sonnet-5-5`, 컷 분석 `claude-opus-5-5` | 지원 | 지원 |
| **OpenAI** | API 키. 설정에서 **키 저장**, 또는 시작할 때 환경변수 `OPENAI_API_KEY` | 없음 (계정에서 쓸 수 있는 모델 ID를 직접 입력) | – | – | – |
| **Codex** | Codex CLI의 ChatGPT 로그인(`codex login`). MomentForge는 키를 받지 않음 | `default` (Codex의 기본 모델) | – | – | – |
| **OpenCode** | OpenCode CLI의 로그인. MomentForge는 키를 받지 않음 | `opencode-go/deepseek-v4.1-flash` | – | 지원 (`opencode models`) | – |
| **CLIProxyAPI** | CLIProxyAPI의 클라이언트 키(`access.api-keys`). 설정 파일에서 자동으로 찾거나 설정에서 **키 저장** | 없음 (모델 목록에서 고름) | – | 지원 | – |
| **OpenCodex** | 없음. 이 컴퓨터의 OpenCodex는 키 없이 받고, 서비스·계정은 OpenCodex 대시보드에서 연결 | 없음 (모델 목록에서 고름) | – | 지원 | – |

- **API 키는 서버 메모리에** 둡니다. 기본으로는 파일·DB·로그에 쓰지 않으므로 앱을 다시 실행하면 다시 넣어야 합니다(환경변수로 넣었다면 그대로 다시 읽음).
- 키를 저장할 때 **이 컴퓨터에도 저장**을 고르면 그 키만 데이터 폴더의 `.env`(권한 0600)에 평문으로 씁니다(`ANTHROPIC_API_KEY=…`, `OPENAI_API_KEY=…`). 다음 실행 때 이 파일을 먼저 읽고, 없으면 환경변수를 읽습니다. 이 파일은 데이터 폴더를 공유·동기화·백업하면 함께 복사되니 주의하세요.
- **키 지우기**는 메모리와 `.env`에서 함께 지웁니다(마지막 키를 지우면 파일도 지움). 환경변수로 넣은 키는 이번 실행에서만 지워지고 다음 실행 때 다시 읽습니다. 고르지 않고 새 키를 저장하면 그 제공자의 키는 `.env`에서 빠집니다.
- 설정 화면은 키가 어디서 왔는지(이 컴퓨터, 환경변수, 이번 실행만) 표시합니다. 화면과 API 응답은 키를 돌려주지 않습니다.
- Claude는 공식 Go SDK로 보내며, `ANTHROPIC_BASE_URL` 같은 환경 설정은 무시하고 화면에서 받은 키(또는 `ANTHROPIC_API_KEY`)만 씁니다. 고정 지시문은 프롬프트 캐싱을 쓰고, 실행 기록에 캐시 적중 토큰을 보여 줍니다. 설정에서 고른 모델이 아닌 다른 모델로 넘기는 서버 측 대체 기능은 켜지 않습니다.
- OpenAI는 Responses API에 `store: false`로 보냅니다. 가격표가 없어 토큰만 표시하고 비용 한도를 쓸 수 없습니다(자동 실행은 요청 수 한도만 적용).
- **앱을 켤 때 자동으로 찾는 것**: Codex CLI와 OpenCode CLI가 설치되어 로그인되어 있으면 "준비됨"이 되고, CLIProxyAPI 설정 파일(`~/.cli-proxy-api/config.yaml`)이 있으면 그 주소(host·port)와 첫 클라이언트 키(`access.api-keys`)를 읽어 바로 쓸 수 있게 합니다. OpenCodex(`ocx`)가 설치되어 있으면 "준비됨"이 되고, 실행 중인 OpenCodex가 받는 포트(꺼져 있으면 `~/.opencodex/config.json`의 포트)로 보냅니다. 찾은 키는 메모리에만 두고 다른 파일에 쓰지 않으며, 설정에서 직접 넣은 키·주소가 있으면 그것을 씁니다. 저장한 기본 제공자가 없으면 화면의 순서(Claude → Codex → OpenCode → CLIProxyAPI → OpenCodex → OpenAI) 가운데 지금 보낼 수 있는 첫 제공자로 시작하고, 설정 화면에 자동으로 골랐다고 표시합니다.
- **Codex**는 [Codex CLI](https://github.com/openai/codex)를 설치하고 `codex login`으로 ChatGPT에 로그인한 뒤 씁니다. MomentForge는 `codex exec`를 실행하며, 셸·브라우저·컴퓨터 사용·앱·플러그인·이미지 생성·웹 검색 도구를 모두 끄고, 사용자의 Codex 설정·규칙을 읽지 않고, 읽기 전용 샌드박스에서 빈 임시 폴더로, Codex 기록을 남기지 않게(`--ephemeral`) 실행합니다. 답은 `--output-schema`로 정해진 JSON 형식만 받고, 도구가 실제로 실행되면 결과를 쓰지 않습니다. 모델 ID를 `default`로 두면 Codex의 기본 모델을 씁니다. 사용량은 ChatGPT 요금제의 Codex 한도에서 쓰이며 비용은 표시하지 않습니다.
- **OpenCode**는 [OpenCode](https://opencode.ai) CLI를 설치한 뒤 씁니다. Go 모델(`opencode-go/…`)은 터미널에서 `opencode`를 실행해 `/connect`로 OpenCode Go를 연결해야 하며 활성 OpenCode Go 구독이 필요합니다. MomentForge가 OpenCode를 직접 실행해 요청을 보내게 하며, `opencode`는 `PATH`, `~/.local/bin`, `~/.opencode/bin`, `/opt/homebrew/bin`, `/usr/local/bin` 순서로 찾습니다. 비용은 OpenCode가 알려 준 값으로 표시합니다. OpenCode Go는 코딩 에이전트용 구독이고 채팅 검토는 코딩 요청이 아니므로, 구독 제한을 받을 위험이 있다는 점을 알고 쓰세요.
- OpenCode의 **무료 모델**(`opencode/deepseek-v4.1-flash-free`, `opencode/glm-5.3-flash-free` 같은 `opencode/…-free`)도 모델 목록에 나오며 구독 없이 씁니다. OpenCode는 무료 등급을 OpenCode 자체 기본 에이전트의 요청에만 응답하므로, 무료 모델은 그 기본 에이전트로 보내고 도구는 모두 "승인 필요"로 두어 CLI가 자동으로 거부하게 합니다(도구가 실제로 실행되면 결과를 쓰지 않음). 지시문은 메시지에 넣습니다. 모델이 도구를 먼저 시도했다가 거부당한 뒤 답하므로 Go 모델보다 조금 느릴 수 있습니다. 무료 모델은 모델마다 데이터 정책이 달라 일부는 무료 기간에 받은 내용을 모델 개선에 쓰거나 30일 보관합니다. [OpenCode Zen 문서](https://opencode.ai/docs/zen)에서 확인하세요.
- **CLIProxyAPI**는 사용자가 실행하는 [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)에 OpenAI 호환 Chat Completions로 보냅니다. 설정의 **CLIProxyAPI 주소**(비우면 `http://127.0.0.1:8317/v1`)와 CLIProxyAPI 설정의 `access.api-keys`에 있는 키를 넣고, **쓸 수 있는 모델 불러오기**로 모델을 고르세요. 어느 서비스·계정으로 갈지는 CLIProxyAPI와 모델 ID가 정합니다. 구독 계정(Claude Code·Codex·Gemini CLI 등)을 API처럼 쓰는 것은 그 서비스의 약관에 어긋날 수 있어 계정이 제한될 수 있습니다. 비용은 알 수 없어 토큰만 표시하고 비용 한도를 쓸 수 없습니다. CLIProxyAPI가 꺼져 있으면 "연결하지 못했습니다"와 주소를 보여 주고, 이때는 아무것도 보내지 않은 것입니다.
  - 준비(macOS 예): [릴리스](https://github.com/router-for-me/CLIProxyAPI/releases)의 `CLIProxyAPI_<버전>_darwin_aarch64.tar.gz`에서 `cli-proxy-api`를 `~/.local/bin`에 두고, `~/.cli-proxy-api/config.yaml`에 `server.host: "127.0.0.1"`, `server.port: 8317`, `access.api-keys`(MomentForge에 넣을 키)를 적은 뒤 `cli-proxy-api -config ~/.cli-proxy-api/config.yaml`로 실행합니다.
  - 켜고 끄기: 설정 화면 CLIProxyAPI 카드의 **CLIProxyAPI 켜기**는 위 명령과 같이 백그라운드로 실행하고 출력은 `~/.cli-proxy-api/cli-proxy-api.log`, 프로세스 번호는 `~/.cli-proxy-api/cli-proxy-api.pid`에 씁니다. MomentForge를 꺼도 CLIProxyAPI는 계속 실행됩니다. **CLIProxyAPI 끄기**는 MomentForge가 켰거나 pid 파일에 적힌, 실제로 `cli-proxy-api`인 프로세스만 끕니다. 다른 방법으로 실행한 CLIProxyAPI는 실행한 터미널에서 끄세요. 주소가 이 컴퓨터가 아니면 켜고 끌 수 없습니다.
  - 대시보드: CLIProxyAPI 설정의 `management.secret-key`(관리 키)를 정하고 `disable-control-panel: false`로 두면, 실행 중일 때 카드에 **CLIProxyAPI 대시보드 열기**가 나와 `http://127.0.0.1:8317/management.html`(CLIProxyAPI Management Center)을 새 탭으로 엽니다. 로그인에는 관리 키가 필요하며, CLIProxyAPI는 시작할 때 설정 파일의 관리 키를 해시로 바꿔 두므로 원래 키는 `~/.cli-proxy-api/management-key.txt` 같은 별도 파일에 두세요(카드가 이 파일 위치를 알려 줌). 대시보드 파일은 CLIProxyAPI가 처음 열 때 공식 GitHub 저장소에서 내려받습니다. `management.allow-remote: false`로 두면 이 컴퓨터에서만 열립니다. 대시보드가 꺼져 있으면 카드가 켜는 방법을 안내합니다.
  - 계정 연결: 같은 명령에 `-claude-login`, `-codex-login`, `-antigravity-login` 같은 옵션을 붙여 실행하면 브라우저에서 그 서비스에 로그인합니다. 대시보드에서도 계정을 연결하고 관리할 수 있습니다. 로그인한 계정이 없으면 모델 목록이 비어 있고, MomentForge는 "CLIProxyAPI가 알려 준 모델이 없습니다"라고 알립니다.
- **OpenCodex**는 사용자가 실행하는 [OpenCodex](https://github.com/lidge-jun/opencodex)(`ocx`)에 OpenAI 호환 Chat Completions로 보냅니다. 이 컴퓨터(127.0.0.1)의 OpenCodex는 키 없이 받으므로 MomentForge에 키를 넣지 않습니다. 설정의 **OpenCodex 주소**(비우면 실행 중인 OpenCodex의 포트, 없으면 OpenCodex 설정의 포트, 기본 `http://127.0.0.1:10100/v1`)로 보내고, **쓸 수 있는 모델 불러오기**로 모델을 고르세요. 어느 서비스·계정으로 갈지는 OpenCodex에 연결한 제공자와 모델 ID가 정합니다. 구독 계정을 API처럼 쓰는 것은 그 서비스의 약관에 어긋날 수 있습니다. 비용은 알 수 없어 토큰만 표시합니다. OpenCodex가 꺼져 있으면 "연결하지 못했습니다"와 주소를 보여 주고, 이때는 아무것도 보내지 않은 것입니다.
  - 준비: `npm install -g @bitkyc08/opencodex`로 설치하고, OpenCodex 대시보드(또는 `ocx init`)에서 쓸 제공자와 계정을 연결합니다. `ocx`는 `PATH`, `~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin` 순서로 찾습니다.
  - 켜고 끄기: 설정 화면 OpenCodex 카드의 **OpenCodex 켜기**는 `ocx start`를 백그라운드로 실행하고 출력은 `~/.opencodex/momentforge-start.log`에 씁니다. 설정에서 주소를 정했으면 그 포트로 켭니다(`--port`). MomentForge를 꺼도 OpenCodex는 계속 실행됩니다. **OpenCodex 끄기**는 `ocx stop`을 실행하므로 터미널이나 서비스로 켠 OpenCodex도 끕니다. OpenCodex 설정에 따라 켜져 있는 동안 Codex CLI도 OpenCodex를 거치고, 끄면(`ocx stop`) Codex가 원래 설정으로 돌아갑니다. 주소가 이 컴퓨터가 아니면 켜고 끌 수 없습니다.
  - 대시보드: 실행 중이면 카드에 **OpenCodex 대시보드 열기**가 나와 `http://localhost:10100/`(주소의 포트)을 새 탭으로 엽니다. 이 컴퓨터에서는 로그인 없이 들어가며, 제공자 연결·계정·모델 선택은 대시보드에서 합니다.
  - OpenCodex 설정의 `hostname`을 `127.0.0.1`이 아닌 주소로 두면 OpenCodex가 모든 요청에 키를 요구합니다. MomentForge는 키 없이 받는 이 컴퓨터의 OpenCodex만 쓰며, 카드가 이 설정을 알려 줍니다.

### 한도와 비용

자동 실행과 **AI 장면 설명 받기**는 작업(세션)마다 **요청 수**(기본 60회)와 **비용**(기본 3달러) 한도 안에서만 보냅니다(설정 › 일반 설정). 자동으로 보낸 실행만 세며, 직접 누른 **AI 컷 분석**은 세지 않습니다. 보내기 전에 계획마다 입력을 UTF-8 바이트 수로 잡은 상한과 요청당 출력 상한으로 **최대 비용**을 계산해, 남은 한도를 넘는 계획은 후보 수를 줄여 맞춥니다. 비용 한도는 가격을 아는 모델(Claude, 공시 가격·기준 시점 2026-10, `internal/ai/anthropic`)에만 적용되고, 실제 비용은 보통 최대값보다 적습니다. 한도에 닿으면 강한 후보부터 보낸 데까지 멈추고 작업 카드 경고("이 작업의 자동 AI 검토 한도에 닿아…")로 알리며, 일반 설정에서 한도를 늘린 뒤 **AI 장면 설명 받기**로 나머지를 보낼 수 있습니다.

배치 전송(Claude Message Batches)과 AI 결과 비교는 AI 검토 탭과 함께 화면에서 뺐습니다. 예전에 보낸 배치는 앱을 켤 때 키가 있으면 결과를 가져옵니다.

## MCP 서버

`momentforge mcp`는 수집한 데이터를 MCP 클라이언트(Claude Desktop, Claude Code)에 **읽기 전용**으로 여는 stdio 서버입니다. 앱 안 AI 기능과 별개로, API 키 없이 사용자의 Claude 구독으로 채팅을 분석하는 방법입니다.

```bash
./bin/momentforge mcp --data /절대/경로/.momentforge
```

- MCP 클라이언트는 다른 폴더에서 이 명령을 실행하므로 실행파일과 `--data`를 **절대 경로**로 적습니다.
- DB를 읽기 전용으로 열기 때문에 `momentforge serve`가 수집하는 동안에도 쓸 수 있습니다. 데이터 폴더의 DB 형식이 실행파일과 다르면 안내를 출력하고 끝납니다.
- 쓰기 도구는 없습니다(수집 시작·삭제 불가). API 키를 읽지 않고 AI 제공자도 쓰지 않습니다.

도구: `mf_list_sessions`(세션 목록), `mf_get_session`(세션 요약), `mf_search_chats`(검색어·작성자 가명으로 채팅 검색), `mf_get_chats_around`(시각 앞뒤 채팅), `mf_list_candidates`(출처별 편집 후보), `mf_get_candidate_context`(후보 편집 구간 채팅과 근거), `mf_get_timeline`(구간별 채팅·작성자 수), `mf_search_utterances`(대본에서 방송자 발언 검색), `mf_get_transcript`(구간의 발언을 시간순으로), `mf_list_cut_plans`(AI 컷 분석 결과: 확정본과 새 버전), `mf_get_cut_plan`(원인과 근거 시각, 경계 후보 세 개, 검수 답·실패 이유, 사용자 메모).

### Claude Code에 등록

```bash
claude mcp add momentforge -- /절대/경로/bin/momentforge mcp --data /절대/경로/.momentforge
```

### Claude Desktop에 등록

Claude Desktop의 설정 파일 `claude_desktop_config.json`(macOS: `~/Library/Application Support/Claude/`, Windows: `%APPDATA%\Claude\`)에 아래 항목을 더하고 Claude Desktop을 다시 시작합니다.

```json
{
  "mcpServers": {
    "momentforge": {
      "command": "/절대/경로/bin/momentforge",
      "args": ["mcp", "--data", "/절대/경로/.momentforge"]
    }
  }
}
```

등록하면 Claude가 도구로 읽은 채팅 본문과 가명 작성자 키가 Claude 서비스로 전달됩니다. 자세한 범위는 [PRIVACY.md](PRIVACY.md#mcp-서버)를 보세요.

## 내보내기와 데이터 폴더

작업 화면 **파일** 탭의 **내보내기**에서 파일을 받을 수 있고, 같은 파일이 데이터 폴더의 `exports/`에 있습니다.

```text
.momentforge/
├─ data/                       SQLite DB (momentforge.db). DB 형식을 올리기 전 backup/에 사본
├─ exports/<작업 ID>/
│  ├─ chat.txt, chat.jsonl     전체 채팅 (시간순) · chat.received.txt (받은 순서)
│  ├─ manifest.json            수집 범위·못 받은 구간
│  ├─ <분석 ID>/               timeline.txt/csv/json, markers/<후보>.txt (앞뒤 채팅·* 근거), analysis-manifest.json
│  ├─ timeline/                통합 타임라인 TXT·CSV·JSON
│  ├─ comments/<수집 ID>/      영상 댓글과 시청자 추천
│  ├─ ai/<실행 ID>/            AI 추천과 실행 기록
│  └─ checkpoints/<시각>/      생방송 현재까지 저장
├─ backups/<작업 ID>/          백업 묶음 (설정에서 다른 폴더로 바꿀 수 있음, 아래)
├─ runtime/                    로컬 접근 키, 서버 중복 실행 방지 잠금, 음성 인식 도우미, audio/(전사용 임시 음성, 끝나면 삭제)
├─ settings.env                설정의 기본값 (비밀 없음)
└─ .env                        "이 컴퓨터에도 저장"을 고른 API 키만 (평문, 0600)
```

### 백업 묶음

작업 화면 **파일** 탭 아래 **백업 묶음**에서 **백업 묶음 만들기**를 누르면, 앱이나 DB가 없어도 그 폴더만으로 다시 편집하고 다시 분석할 수 있는 묶음을 만듭니다. 기본 위치는 데이터 폴더의 `backups/<작업 ID>/`이고, 설정의 **백업 묶음** 탭에서 다른 폴더(NAS에 마운트한 공유 폴더 등, 전체 경로)로 바꿀 수 있습니다.

```text
backups/<작업 ID>/
├─ manifest.json               묶음 형식·버전, 작업 정보, 시간축(video_offset_ms), 파일마다 크기와 SHA-256
├─ README.txt                  이 묶음이 무엇이고 어떻게 쓰는지
├─ video.mp4 · video.json      다시보기 영상(재인코딩 없음)과 화질·조각 수·빠진 구간
├─ chat.jsonl · chat.txt · chat-manifest.json
├─ transcript.json · .srt · .vtt   최신 대본
├─ timeline/ · analysis/<분석 ID>/ · comments/
├─ cuts/<계획 ID>/ · cuts/confirmed.*   컷 계획 모든 버전과 확정본
├─ ai-runs/<실행 ID>.json      AI에 보낸 내용·모델·토큰·비용 (키 없음)
└─ notes.md                    확정한 컷과 남긴 메모
```

- **영상**: **영상 포함**을 켜면(설정의 기본값, 처음에는 켜짐) 치지직 공개 다시보기를 설정한 화질(기본 720p) 이하에서 가장 높은 화질로, 재인코딩 없이 조각을 이어 붙여 `video.mp4`로 받습니다. 첫 조각이 0초가 아닌 시각에서 시작하므로 조각의 시각을 당겨 **영상 파일의 0초가 채팅·발언·컷 시각의 0초와 같게** 맞춥니다(`video_offset_ms = 0`). 720p 3시간이 약 4GB입니다.
- **중단과 이어받기**: 채팅·분석 같은 파일을 먼저 쓰고 영상을 받습니다. 작업 카드의 **작업 중단**이나 연결 오류로 멈추면 받은 곳까지 남기고, 다시 누르면(**영상 이어받기**) 그 자리부터 받습니다. 로그인·유료·암호화 영상처럼 받을 수 없는 영상은 영상 없이 묶음을 마치고 이유를 적습니다.
- **NAS 백업에서 불러온 작업**은 영상을 복사하지 않고 원래 경로를 `manifest.json`의 `video.ref`에 적습니다.
- **다시 만들기**: 바뀐 파일만 바꿔 쓰고, 이 앱이 전에 쓴 파일 중 없어진 것만 지웁니다. 폴더에 직접 넣은 다른 파일은 지우지 않습니다. 받은 영상은 **영상 포함**을 끄고 다시 만들어도 남습니다.
- editnest에서 자르기: 타임라인 메모에서 `video.mp4`를 열고 `cuts/confirmed.editnest.json`을 **JSON 불러오기**로 넣은 뒤 구간 받기의 **타임라인 메모에서 가져오기**를 누릅니다.
- 생방송 기록은 아직 묶음을 만들 수 없습니다(방송이 끝난 뒤 다시보기로 수집).

채팅 TXT 한 줄은 `[영상 시각][가명 작성자][메시지 ID] 본문` 형식입니다. 데이터 폴더에는 채팅 원문과, 저장을 고른 경우 API 키가 있으므로 공유·클라우드 동기화·백업 대상에 넣을 때 주의하세요.

**목록에서 모두 숨기기**와 **숨긴 작업 다시 표시**는 홈의 저장 목록 표시만 바꿉니다. 채팅·분석·내보낸 파일은 지우지 않습니다. 자료를 지우려면 앱을 끈 뒤 데이터 폴더를 직접 삭제하세요.

## 보류한 기능과 아직 없는 기능

보류한 기능 (CzzEdit에 있었지만 옮기지 않음, 필요해지면 별도 계획):

- **본인 시청 계정 로그인 VOD**: 로그인이 필요한 다시보기는 "아직 지원하지 않습니다"라는 안내와 함께 수집하지 않습니다.
- **공식 API 시청자 수 기록**(개발자 Client ID/Secret 사용): 공개 웹 시청자 수 기록과 보정은 그대로 있습니다.

아직 없는 기능: 생방송 여러 채널 동시 수집, 생방송 기록과 다시보기 시각 연결, 치지직 외 플랫폼, 생방송 전체 음성 인식(지금은 판정한 후보 구간만), 생방송 잠정 컷 분석, 채팅 전송.

## 확인 범위

- 다시보기 수집·재생·후보 이동과 생방송 30분 넘는 연속 수집·중단·이어 기록은 실제 치지직 방송으로 확인했습니다.
- 생방송 영상은 실제 치지직 공개 방송 하나로 확인했습니다(1080p 재생, 멈추면 받기 중단, 수집 중단 시 영상 정지, 재생 주소 미저장). 연령 제한·유료·종료된 방송의 안내는 가짜 응답으로만 확인했고, 재생 도중 방송이 끝나는 경우는 아직 확인하지 못했습니다.
- CzzEdit 0.3.2 기준값으로 분석하면 같은 채팅에서 CzzEdit와 후보·통계가 필드 단위로 일치합니다(Go 테스트로 고정). 기본 판정 기준은 그 뒤 채널 규모에 맞춘 방식으로 바꿨습니다.
- 백업 묶음의 영상 받기는 합성 조각(Go 테스트)과 가짜 플랫폼(`make e2e`)으로 확인했습니다. 실제 공개 다시보기 하나(3시간 1분)를 360p로 끝까지 받아, macOS(AVFoundation)가 전체 길이를 읽고 SHA-256이 맞는 것까지 확인했습니다. editnest에서 자르기는 아직 확인 중입니다.
- 화면 흐름은 가짜 플랫폼·가짜 AI 제공자를 넣은 전용 실행파일로 `make e2e`에서 확인합니다. 배포용 `bin/momentforge`에는 가짜 플랫폼이 들어가지 않습니다.
- 생방송 단계 판정(예비 → 5분 판정 → 확정)과 생방송 음성 녹음·후보 구간 인식, 자동 AI 검토(대본 다듬기·장면 설명)는 가짜 플랫폼·가짜 음성 인식·가짜 AI와 Go 테스트(치지직 재생 목록은 가짜 HLS 서버)로 확인했습니다. 실제 치지직 생방송에서 음성 조각 형식(fMP4·MPEG-TS)과 Apple 음성 인식이 그것을 읽는지, 예비 후보가 판정에 남는 비율, 실제 AI 제공자로 자동 실행한 비용은 아직 확인하지 않았습니다.
- 실제 API 키를 쓴 Claude·OpenAI 호출, OpenCode Go 구독 모델의 정상 응답, 실제 CLIProxyAPI 연결, 실제 OpenCodex에 채팅을 보낸 응답, 시각이 적힌 실제 영상 댓글은 아직 확인 중입니다. OpenCode 무료 모델은 샘플 채팅으로 실제 실행을 확인했습니다(2026-10-17). OpenCodex 2.55.0-preview는 설정 카드의 켜기·실행 상태·대시보드 열기(로그인 없이 열림)·모델 목록·끄기를 실제로 확인했습니다(2026-10-17).
- macOS에서 개발·확인했습니다. Windows·Linux에서의 빌드와 실행은 아직 확인하지 않았습니다.

문제를 알릴 때는 OS, `momentforge version` 결과, 화면의 오류 문구, 재현 순서를 알려 주세요. DB, 내보낸 채팅, API 키는 공개 첨부하지 마세요.

## 개발

| 명령 | 내용 |
|---|---|
| `make dev` | Go 서버(8765) + Vite 개발 서버(5173) 동시 실행 |
| `make build` | 화면 빌드 → 실행파일에 넣기 → `bin/momentforge` |
| `make test` | 구조 검사 + gofmt + go vet + go test + 화면 타입 검사 |
| `make e2e` | 가짜 생방송·가짜 AI를 넣은 `bin/momentforge-e2e`로 Playwright 정상 작동 테스트 (Python 3.9 이상) |
| `MF_CUT_EVAL_DATA=<데이터 폴더> go test ./cmd/momentforge -run TestCutEvalReport -v` | 저장된 컷 분석 결과를 `e2e/cut-eval/cases/`의 정답과 비교한 보고서 (읽기 전용, AI에 보내지 않음). 사용법은 [e2e/cut-eval/README.md](e2e/cut-eval/README.md) |

설계와 결정 기록은 [docs/REDESIGN.md](docs/REDESIGN.md), 화면 디자인은 [docs/DESIGN-SYSTEM.md](docs/DESIGN-SYSTEM.md), Claude Code 개발 지침은 [CLAUDE.md](CLAUDE.md)에 있습니다.
